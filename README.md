# 山地地质灾害隐患巡查与治理工作台

面向隐患点建档、坡体形变与裂缝观测、雨量预警发布、避险搬迁与治理工程验收的山区地质灾害防治工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 发版与回退

发版前有一道自检闸口，别再改完就发：

```bash
make release
```

闸口依次做四件事，任何一步不过都会卡住本次发版：

1. **类型检查**：`vue-tsc --noEmit`，报错文件逐条列出；
2. **依赖校验**：对照 `package.json` 核查安装结果，缺失依赖逐条列出；
3. **工作区检查**：有未提交改动就拦下（干净目录验证不到未提交的内容）；
4. **干净目录验证**：把仓库克隆到系统临时目录，装上依赖再打包，必须一次通过，
   保证本地开发环境与打包产物一致；脚本路径全部由自身位置推导，不写死。

全部通过后，干净目录里打出来的产物归档到 `releases/<版本号-时间戳>/` 并同步到
`frontend/dist`，发版记录写在 `releases/manifest.json`。

退回上一版：

```bash
make rollback
```

按 `releases/manifest.json` 把当前版的前一版恢复到 `frontend/dist`。

## 业务规则（支挡结构）

- **状态逐段推进**：待浇筑 → 施工中 → 待验收 → 已验收，只能一段一段走，跳级一律拦下。
- **重复导出只认先到的那一份**：导出内容没变再点导出，直接拦下，以首次导出为准。
- **导出回写巡查待办**：每次有效导出办完，群测群防巡查会多出一条「待巡查」待办。
- **结构形式统一取数**：候选值只有 `frontend/src/data/wall-forms.ts` 一份，登记、筛选、
  元数据都从这里取；同一工程已有支挡记录时，新登记沿用既有记录里的结构形式，不回炉。
- **结构长度精度**：大于 0、最多两位小数（精确到厘米），精度不对的直接退回，不落库。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `geohazard-patrol:entries` 这一项，或调用 `resetModule(模块)`。
